# Автопостинг во все каналы бота

Идея: твой скрипт создаёт каналы и добавляет туда бота (админом, с правом
постить). Раньше контент публиковался только вручную (`python post.py`).
Теперь есть два способа:

- **`bot.py`** — постоянно работающий бот. Сам постит по расписанию
  (10:00 и 20:00 по МСК) и даёт две кнопки в Telegram, чтобы посмотреть
  статус и запостить внепланово. **Рекомендуемый способ.**
- **`post.py`** — как и раньше, разовый запуск из консоли вручную
  (например, если `bot.py` сейчас не запущен).

Оба используют одну и ту же базу каналов `channels.json` и общую логику
постинга из `posting.py` — ничего из старого поведения не потерялось.

## Установка

```bash
pip install -r requirements.txt
```

Впиши токен бота в `config.py` (`BOT_TOKEN`) — токен берётся у **@BotFather**
в Telegram (команда `/newbot` или `/token`, если бот уже создан там) и должен
принадлежать **тому же боту**, которого твой скрипт-создатель добавляет в
новые каналы.

Для `bot.py` также впиши в `config.py` свой Telegram user id в `ADMIN_IDS`
(без этого бот никого не пустит к кнопкам). Узнать свой id можно у
`@userinfobot`.

## Хостинг на bothost.ru

Проект рассчитан на постоянную работу `bot.py`, поэтому его лучше держать не
на своём компьютере, а на хостинге — например, на **bothost.ru**:

1. Залей папку проекта в Git-репозиторий (GitHub) — bothost.ru умеет
   разворачивать бота прямо из репозитория по одному клику и подхватывать
   обновления при `git push`.
2. В настройках проекта на bothost.ru укажи:
   - язык — **Python**;
   - файл зависимостей — `requirements.txt` (он уже в проекте);
   - команда запуска — `python bot.py`.
3. Токен (`BOT_TOKEN`) и список админов (`ADMIN_IDS`) можно оставить прямо
   в `config.py`, как сейчас — просто не выкладывай репозиторий в публичный
   доступ, раз токен лежит в коде.
4. Прокси на bothost.ru не нужен — сервер напрямую достаёт до
   `api.telegram.org`, поэтому в `config.py` он по умолчанию выключен
   (`PROXY_URL = None`). Трогать не нужно, если только хостинг не поменяется
   на такой, где Telegram заблокирован напрямую.
5. `channels.json` — база каналов — тоже должен уехать вместе с проектом
   (лежит в репозитории); дальше `bot.py` сам будет держать его в
   актуальном состоянии.

После этого просто следи, что процесс `bot.py` на bothost.ru отмечен как
"запущен" (running) — панель хостинга обычно сама перезапускает его при
падении.

## Важное требование к боту в каналах

Бот должен быть добавлен как **администратор** с правом
"Публикация сообщений" (`can_post_messages`) — иначе `send_photo`/`send_message`
в канал вернёт ошибку. Если твой скрипт добавляет бота просто участником —
нужно доработать его, чтобы делал `promoteChatMember` с этим правом
(или использовать `bot.promote_chat_member(...)` на этапе создания канала).

## Автопостинг по расписанию и кнопки (`bot.py`)

```bash
python bot.py
```

Процесс должен работать постоянно (не разово) — например, в `systemd`,
`screen`/`tmux`, Docker-контейнере или как соответствующий сервис у хостера.
Пока он работает:

- Каждый день в 10:00 и в 20:00 по МСК бот сам синхронизирует каналы и
  постит в них фото + текст (те же `DEFAULT_TEXT`/`DEFAULT_IMAGE` из
  `config.py`). Времена задаются списком `POST_TIMES` в `config.py` —
  можно поменять или добавить ещё.
- Напиши боту `/start` (с аккаунта из `ADMIN_IDS`) — придёт сообщение с
  двумя кнопками:
  - **📊 Статус** — обновляет то же сообщение: работает бот сейчас или
    идёт постинг в данный момент, сколько каналов в базе, время
    следующего автопостинга, результат последнего запуска (когда, вручную
    или по расписанию, сколько успешно/с ошибками).
  - **🚀 Запостить сейчас** — запускает внеочередной постинг сразу же
    (сначала сообщение меняется на «⏳ Идёт постинг…», по завершении —
    на итоговую статистику: сколько каналов успешно, сколько с ошибкой).
  Обе кнопки просто редактируют одно и то же сообщение, а не шлют новые.
- О результате автопостинга по расписанию бот также сам пришлёт сообщение
  каждому из `ADMIN_IDS`.
- Пока бот работает, он в реальном времени отслеживает добавление/удаление
  из каналов (апдейты `my_chat_member`) и сразу обновляет `channels.json` —
  ограничение Telegram на ~24 часа хранения апдейтов (см. ниже) в этом
  режиме уже не актуально.

## Разовый запуск вручную (`post.py`)

```bash
# Обычный запуск: синхронизация + постинг во все каналы
python post.py

# Другой текст и картинка на этот раз
python post.py --text "Текст сегодняшнего поста" --image today.jpg

# Проверить, куда бы запостил, ничего не отправляя
python post.py --dry-run

# Пропустить синхронизацию (если точно знаешь, что новых каналов нет)
python post.py --no-sync
```

⚠️ Не запускай `post.py` одновременно с работающим `bot.py` — оба общаются
с Telegram через один и тот же токен бота, и не должно быть двух процессов,
конкурирующих за одну и ту же учётную запись бота. Если `bot.py` работает
постоянно, отдельный `post.py` для регулярного постинга уже не нужен —
только для разовых ручных постов, пока `bot.py` не запущен.

## Как это работает "под капотом"

- Когда бота добавляют в канал администратором, Telegram присылает боту
  апдейт `my_chat_member`.
  - Если работает `bot.py` — он ловит такие апдейты сразу, в реальном
    времени, и сохраняет каналы в `channels.json`.
  - Если используется только `post.py` — апдейты читает `sync_channels.py`
    через `getUpdates` при каждом запуске.
- ⚠️ Ограничение (актуально только при использовании одного `post.py`
  без `bot.py`): непрочитанные апдейты Telegram хранит примерно **24 часа**.
  Если между добавлением бота в канал и запуском `post.py` пройдёт больше
  суток, апдейт может быть потерян, и канал не попадёт в список
  автоматически. Варианты решения:
  - запускать `post.py` не реже раза в день;
  - либо (что уже сделано) держать постоянно работающий `bot.py` — он ловит
    такие апдейты сразу и это ограничение не имеет значения.
- `channels.json` — просто список каналов, его можно и вручную
  подправить/добавить chat_id, если что-то пошло не так. Сейчас в нём уже
  прописаны два канала с именем-заглушкой `"имя"` — это только отображаемое
  название для статуса, на сам постинг оно не влияет (постит по chat_id).
  Если хочешь, впиши туда настоящие названия каналов вручную — автоматически
  они обновятся только при новом апдейте `my_chat_member` (например, если
  бота удалить из канала и добавить заново).
- `offset.json` — служебный файл для `sync_channels.py`/`post.py`, чтобы
  Telegram не присылал одни и те же апдейты повторно. Не трогай его руками.
  `bot.py` его не использует (он получает апдейты через собственный
  непрерывный поток `run_polling`).

## Частые проблемы

- **"Not enough rights to send text messages"** — у бота в канале нет права
  постить, нужно выдать право `can_post_messages`.
- **Канал не появляется в channels.json** — проверь, что бота добавили
  именно с токеном из `config.py`. Если используешь `bot.py`, канал должен
  появиться сразу; если только `post.py` — не позже чем через сутки после
  добавления (см. ограничение выше).
- **Бот кикнут из канала** — при следующей синхронизации (или сразу, если
  работает `bot.py`) канал автоматически уберётся из списка.
- **Бот не отвечает на /start и кнопки** — проверь, что твой Telegram user
  id добавлен в `ADMIN_IDS` в `config.py`.
